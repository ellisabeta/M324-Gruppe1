# P2 – Git- und Review-Prozess

- Für jede Aufgabe wird ein kurzlebiger Feature-Branch erstellt, zum Beispiel `feature/P2-airport-service`.
- Der Branch wird regelmässig mit `main` abgeglichen.
- Änderungen werden über einen Pull Request eingereicht.
- Vor dem Merge müssen die CI-Tests erfolgreich sein.
- Jeder Pull Request wird von mindestens einer weiteren Person geprüft.
- Danach wird der Pull Request per Squash-Merge in `main` übernommen.
- Direkte Commits auf `main` werden vermieden.
